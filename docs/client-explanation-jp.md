# Azure AI Agent Chatbot ご説明資料

## 1. ご提案の概要

本システムは、社内に蓄積された文書ナレッジ、業務データ、レポート情報を自然言語で活用できる AI Agent Chatbot です。  
ユーザーは Web 画面、Teams、または企業ポータルから質問を入力するだけで、社内文書に基づく回答、関連資料の引用、業務指標の分析、Power BI レポートへの誘導を受けられます。

基盤には Microsoft Azure のサービスを採用します。アプリケーションは Azure VM / Azure VMSS 上で稼働し、AI 応答には Azure OpenAI / Azure AI Foundry、文書検索には Azure AI Search、データ分析には Microsoft Fabric と Power BI Semantic Model を利用します。

## 2. 解決できる課題

多くの企業では、業務マニュアル、FAQ、契約関連資料、運用手順、売上データ、Power BI レポートなどが複数の場所に分散しています。そのため、必要な情報を探すだけで時間がかかり、担当者への問い合わせも増えやすくなります。

本システムでは、これらの情報を AI Agent から横断的に利用できるようにします。ユーザーは「この手続きはどうすればよいか」「先月の売上が下がった理由は何か」「関連するレポートを見たい」といった質問を自然な文章で入力できます。AI Agent は質問内容を判断し、文書検索、データ分析、レポート参照のいずれが必要かを選択して回答します。

## 3. システム全体の考え方

本システムは、以下の 3 つの役割に分けて設計します。

- Azure AI Search は、PDF、Word、Markdown、FAQ などの非構造化文書を検索するために利用します。
- Microsoft Fabric は、ERP、CRM、SQL、Excel、API などの業務データを集約し、分析しやすい形に整備するために利用します。
- Azure OpenAI / Azure AI Foundry は、ユーザーの質問理解、回答生成、分析結果の要約、Agent のツール選択に利用します。

アプリケーション本体は Azure VM / Azure VMSS に配置します。VM 上では Nginx、React フロントエンド、FastAPI API、Agent Router、Tool Gateway を稼働させます。これにより、既存システムとの連携、ネットワーク制御、ログ管理、段階的な拡張を行いやすい構成にします。

## 4. ナレッジ検索の仕組み

社内文書は、まず Blob Storage または OneLake Files に格納します。その後、文書解析、OCR、chunk 分割、metadata 付与、embedding 生成を行い、Azure AI Search のインデックスに登録します。

ユーザーが文書に関する質問を入力すると、Agent は質問を検索に適した形へ変換し、キーワード検索とベクトル検索を組み合わせた Hybrid Search を実行します。さらに Semantic Ranker により検索結果を並べ替え、関連性の高い文書だけを回答生成に利用します。

回答には、根拠となった文書やセクションを引用元として表示します。十分な根拠が見つからない場合は、推測で回答せず、該当情報が見つからないことを明示します。これにより、AI の回答に対する信頼性と説明責任を確保します。

## 5. レポート分析の仕組み

売上、在庫、利益、顧客数、問い合わせ件数などの構造化データは Microsoft Fabric に取り込みます。Fabric 内では OneLake、Lakehouse / Warehouse、Power BI Semantic Model を利用し、業務指標の定義や分析用データを管理します。

ユーザーが「今月の売上は前年同月比でどう変化したか」「利益率が低下している部門はどこか」と質問すると、Agent はレポート分析の質問であると判断します。その後、Fabric Data Agent、SQL、DAX、Power BI API などの適切なツールを呼び出し、認定済みの指標定義に基づいて結果を取得します。

取得した数値や集計結果は、Azure OpenAI により自然な説明文へ変換されます。必要に応じて、Power BI の該当レポートリンクもあわせて提示します。これにより、単なる数値確認だけでなく、傾向、異常、原因候補を会話形式で確認できます。

## 6. セキュリティと運用

本システムは、企業利用を前提としてセキュリティと運用性を重視します。

- Microsoft Entra ID による SSO、MFA、ユーザーグループ連携を行います。
- Managed Identity を利用し、Azure サービス間のアクセスをパスワードレス化します。
- Key Vault により、キー、証明書、設定値を安全に管理します。
- Private Endpoint と VNet により、重要サービスへの通信を閉域化します。
- Application Insights、Log Analytics、Azure Monitor により、API 応答時間、エラー、検索品質、利用状況を監視します。

また、文書検索では `securityGroups` などの metadata を利用し、ユーザーの権限に応じた文書だけを検索対象にします。レポート分析では Power BI Semantic Model の RLS を利用し、ユーザーごとに参照可能なデータを制御します。

## 7. 導入後に期待できる効果

導入により、社内情報の検索時間を短縮し、問い合わせ対応の負荷を減らすことができます。新人や異動者は、業務マニュアルや過去のナレッジを自然言語で確認できるため、業務理解を早められます。

また、Power BI レポートや Fabric 上のデータを Chatbot から利用できるため、経営層や現場担当者が必要な指標を素早く確認できます。専門的な SQL や DAX を直接書かなくても、認定済みの指標に基づく分析結果を得られる点が大きなメリットです。

## 8. 導入ステップ

導入は、PoC、パイロット、本番展開の 3 段階で進めることを推奨します。

1. PoC フェーズ  
   対象文書と一部の業務データを使い、ナレッジ検索とレポート分析の基本機能を検証します。

2. パイロットフェーズ  
   対象部門を限定し、実ユーザーによる利用を開始します。検索精度、回答品質、権限制御、運用ログを確認します。

3. 本番展開フェーズ  
   Entra ID、Managed Identity、Private Endpoint、監視、バックアップ、運用手順を整備し、全社または対象部門へ展開します。

## 9. まとめ

本システムは、社内文書の検索、業務データの分析、Power BI レポートの活用を 1 つの AI Agent Chatbot から利用できるようにする仕組みです。  
Azure AI Search、Microsoft Fabric、Azure OpenAI / Azure AI Foundry、Azure VM / VMSS を組み合わせることで、Microsoft Azure 上で実装しやすく、セキュリティと拡張性を考慮した構成を実現します。

最初は限定された文書とデータで PoC を行い、効果を確認しながら段階的に対象業務を広げることで、低リスクかつ現実的に導入できます。
